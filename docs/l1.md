# L1 grammar and candidate contract

The native grammar recognizes a bounded subset of TypeScript modules, a restricted control program, and a limited set of TSX initializers. Lexical rules operate on UTF-8 with ASCII identifiers and punctuation. The grammar below illustrates the control and JSX subset used by the reference model and initial native entry points. The module and expression extensions are described below it.

```text
file        ::= trivia (declaration ";"? | control statement* | var-init ";" statement*)? trivia EOF
declaration ::= "export"? "const" identifier "=" (parameter "=>" result | result)
parameter   ::= "(" identifier ":" "number" ")"
result      ::= comparison | element
comparison  ::= atom (operator atom)?
atom        ::= (identifier | "this") ("." property)* | decimal | "(" comparison ")"
operator    ::= "<" | "<=" | ">" | ">="
element     ::= "<" jsx-name attribute* "/" ">"
attribute   ::= jsx-name "=" (jsx-string | "{" comparison "}")
control     ::= "if" "(" comparison ")" block ("else" block)?
              | "while" "(" comparison ")" block
              | "do" block "while" "(" comparison ")" ";"?
              | "for" "(" (("let" | "var") identifier "=" comparison)? ";" comparison? ";" update? ")" block
block       ::= "{" statement* "}"
statement   ::= control | update ";" | ";"
var-init    ::= "var" identifier "=" comparison
update      ::= identifier ("++" | "--")
```

The ordinary lexical mode skips spaces, tabs, LF, CR, CRLF, U+2028, U+2029, and UTF-8 line and block comments. A hashbang at byte zero uses the same line terminators and preserves original byte positions. A line break, including one in a block comment, is forbidden between the parameter's closing parenthesis and the arrow. Identifiers have the ASCII structure of JavaScript identifiers without escapes and exclude reserved words. Declaration and parameter names also exclude `eval` and `arguments`. JSX names allow hyphens after the first character and have no reserved-word restriction. An unsigned decimal is an ASCII digit sequence with no leading zero except the literal zero. JSX attribute strings have matching single or double quotes and may contain UTF-8, including comparison punctuation. JSX tag delimiters use the tag whitespace rules. Tokens around opening-tag attributes accept ordinary whitespace and comments. In an attribute expression the ordinary lexical mode resumes.

Property names after a dot use ASCII identifier characters and may be reserved words. Prefix and postfix update expressions use the simple assignment-target rules. A postfix update permits no line break before the operator. A `var` loop initializer is allowed in a standalone file-scope control program. Classic loop heads admit bounded expression lists and typed `let` or `const` binding lists, including nested patterns. A simple `var` initializer is supported in a function. Loop bindings use a nested scope and are restored when the loop ends. The `var` reader accepts simple typed or initialized bindings. The bounded native route delegates a function that mixes `var` with potentially conflicting lexical declarations. Collection loops use `let` or `const` with an identifier or a bounded nested binding pattern. A switch can contain case tests, a single optional default clause, and a shared lexical scope. Unlabelled `break` requires an enclosing loop or switch. Unlabelled `continue` requires an enclosing loop. Both permissions reset at a function boundary. Try, catch, and finally bodies are explicit blocks. A catch can have no binding, a named binding, or a bounded nested binding pattern.

The module grammar accepts side-effect, named, default, and namespace imports and type-only default and named imports. Dynamic `import()` accepts a specifier and optional options expression. The `import.meta` expression is available throughout a module. Variables can bind simple names or nested object and array patterns, with array elisions, simple defaults and a final named rest binding. Simple mutable declarations can use a definite assignment marker with a type annotation. Default exports support assignment expressions and named or anonymous function and class declarations. A default export can appear once per module. Name tables distinguish module types from values and reserve both namespaces for imports and classes. Plain and type-only star and named re-exports accept a quoted source. Named re-exports support ASCII aliases, including `default`. Empty export lists are supported. Nonempty local export lists delegate for forward resolution. Simple `declare const`, `declare let` and `declare var` bindings require annotations. Nested function declarations, named and anonymous function expressions, and ordinary and async object methods share the bounded function-body parser. Named functions support optional typed parameters and default expressions. Functions can contain local type aliases, including the single statement of a control body. Function and arrow parameter lists admit a simple rest binding in the final slot. Await expressions and `for await…of` are available in modules and async bodies, with a fresh permission at every function boundary.

Class declarations can use bounded type parameters, a simple qualified base, and an implements list. The fast path reads uninitialized and initialized fields, and supported ordinary, static, async, accessor, generator and constructor methods. ASCII identifier method names, including override and access-modified methods, can have adjacent typed overload signatures followed by an implementation with the same name and modifiers. A constructor may have adjacent typed signatures before its single implementation. Default exports can declare an abstract class, and typed constructor parameter properties can infer their type from an initializer. Adjacent named default function overloads with the same name and async modifier consume a single export and require a matching implementation. Methods can access `super` properties and derived constructors can call `super`. Arrows inherit these permissions. Ordinary functions reset them.

ASCII private fields, methods and ordinary dot accesses participate in the native grammar. The parser records a bounded log of class scopes, declarations and accesses, including references that precede their declaration. Validation checks duplicates and lexical ownership before candidate publication. A full log has 255 events. Private brand checks, optional private chains, and private accessors delegate.

Explicit script mode also uses the expanded statement sequence, including CommonJS assignments and dynamic imports. An initial exact `"use strict"` or `'use strict'` directive with an explicit semicolon or a recognized automatic semicolon boundary enables nested function declarations in explicit blocks inside functions. Static imports, exports and import meta syntax retain their module requirements. The reader supports ordinary and const TypeScript enum declarations with bounded member initializers.

Generator declarations, default exports, and generator methods of classes and object literals can use the existing `yield` statement and delegated `yield*` grammar. The yield permission belongs to the generator body. Nested ordinary functions reset it. Ambient generator declarations, bodyless generator signatures, and generator constructors delegate.

Destructuring defaults can use the bounded expression parser, including qualified members, calls, class expressions and comparisons. Variable slots stay reserved while a default is parsed. Collection loop heads accept a simple existing identifier and a simple function-local `var` when the existing binding-mode restrictions are met. Plain and type-only star re-exports can use an ASCII namespace alias. Conditional tuple constraints accept direct `infer` elements with their own `extends` bounds.

Named module-level abstract classes admit typed bodyless properties and methods. Computed class fields, class methods and binding keys admit identifiers, qualified identifier chains and unescaped quoted strings of ASCII identifier characters. Module classes admit ordinary optional typed signatures, including generic signatures, and declaration-only typed fields with `declare` first. Required and optional declaration fields may use supported property names and access, static or readonly modifiers. Flat parenthesized object assignment patterns can write to existing simple names and dotted members, including members rooted at `this`. The read-only pattern lookahead leaves ordinary object expressions on the existing expression path. A noncomputed object literal key in colon form can set the prototype once per object. Constructor calls support `this`, parenthesized operands and a computed index in a qualified target. A closing call parenthesis can resolve a less-than operator followed by a trailing argument comma. The regex reader accepts selected category and identifier-property escapes and bounded code-point escapes in Unicode mode. Ordinary functions, class methods and field initializers admit `new.target`; arrows inherit that context.

The type grammar accepts named and qualified references, nested type arguments, numeric, string and template literal types, bounded conditional types with inferred names, arrays, labeled, rest and optional generic tuple elements, indexed access, grouped and function types, and object types with computed and ordinary properties, typed indexes, call signatures, constructor signatures and generic methods. Type aliases, interfaces, and named functions can use bounded type parameter lists with constraints and defaults. Interfaces accept canonical in and out variance modifiers, including in out. Object types support identifier getter signatures with empty parameters, and typed signatures may end with a single-name object binding. Interfaces accept bounded lists of qualified base references. Quoted ambient modules accept bodies containing plain or exported interfaces, which may merge. Function-like result positions admit type predicates and assertion signatures. A typed leading `this` parameter has no runtime binding. Type operators include `keyof` and qualified `typeof` queries. A quoted module specifier is supported in import types.

The expression parser uses precedence for comparisons, relational `in` and `instanceof`, arithmetic, equality, bitwise and logical operators, shifts, conditionals, and assignments. Assignments associate to the right and allow a postfix non-null assertion on a supported target, including a simple name, member, or computed target. Other supported forms include selected unary operators, `delete` on member and optional-chain expressions, strings, bounded numeric literals, template substitutions, calls, qualified constructors, sparse arrays, spreads, and computed names for object properties and methods. String values and template segments support fixed-width hexadecimal and Unicode escapes, bounded Unicode code points, and escaped line endings. Tagged templates retain the full tag and template span, including tags followed by a line break. The reader preserves raw escape spellings and parses substitutions. Calls with attached type arguments use read-only lookahead before the call parser consumes arguments. Named and qualified constructors may omit the argument list at a closing delimiter or end of input. A line break can also end the construction before a supported declaration, loop, or dotted member statement. Generic instantiation expressions may end at a statement or expression delimiter. Member, index and call chains can use optional access. Nullish coalescing requires parentheses when mixed with `&&` or `||`. Arrow functions support type parameters, typed parameters with simple defaults, bounded nested binding patterns, return annotations, and expression or block bodies. In TSX the generic head must have a comma, constraint or default to distinguish it from an opening tag. TypeScript `as` and `satisfies` operators and postfix non-null assertions require no preceding line break. Unsupported angle bracket forms, including generic tags, and unsupported operators decline the entire file.

The regex literal reader supports character classes and ranges, basic escapes including `\0` without a following decimal digit, numeric references to captures already opened, balanced capturing and noncapturing groups, ASCII named captures, lookarounds, alternation, quantifiers, and distinct `d`, `g`, `i`, `m`, `s`, `u`, and `y` flags. Raw BMP scalars can occur as atoms or range endpoints. Character classes can also contain isolated fixed-width surrogate escapes. Adjacent Unicode escape pairs remain delegated. Range ordering uses the decoded values. Raw line separators, astral scalars and the `v` flag delegate. Outside character classes, the non-Unicode grammar supports `\:`, a bare `]`, and a bare `{` when the next byte is outside the decimal digit range. These forms require legacy regex mode. The flat scanner uses a loop in generated C. Group nesting is bounded at 32 and counted quantifiers use at most six decimal digits. Unrecognized regex forms delegate with the rest of the source.

TSX uses the expression parser for self-closing and paired elements, fragments, and nested JSX. Attribute values can be quoted, braced or nested JSX, and openings can use boolean and spread attributes. Inside children, raw text uses JSX lexical rules and braces return to ordinary expression parsing. Tag closures must match the opening name. A direct disjunction in a `disabled` attribute delegates to preserve the focused logical rewrite.

Constrained infer types are supported inside template type interpolations and object property annotations. A type signature can end with a typed object parameter containing up to sixteen plain shorthand bindings. Quoted property names accept fixed non-ASCII Unicode escapes. Escaped ASCII spellings that could affect special property names are delegated.

The module grammar records up to 512 top-level bindings and up to 512 bindings across the currently open function and block scopes, including parameters. A third region tracks up to 512 export names separately. Individual lists retain their own bounds. Speculative parameter and collection heads use scratch entries above the active scope. Arrow blocks share the statement parser's recursion budget, and closing a block restores the caller's active names. Duplicate or oversized bindings decline the entire module. If both recognizers decline an input, no partial candidates are published.

Direct script and module `var` declarations use the same binding table as lexical declarations, including conflict checks. A leading script var enters the expanded statement reader first so an automatic semicolon after a long initializer does not trigger a full reparse. The restricted control reader is still available for its root control forms. Module mode alone enables static imports and exports and module-level await. Ordinary block and module statement lists can declare initialized resources with `using`; async contexts also support `await using`. Resource declarations share the lexical binding checks and admit identifier names. Direct switch clauses and script top levels stay on the compatibility path for these declarations. The module reader also accepts a terminal TypeScript `export = expression` following imports and declarations with no registered named or default export. In script functions a recognized raw strict directive, or inherited strict context, enables exact function-local var scoping. The expanded parser can defer up to 64 local export lists and checks their unresolved names against the completed module bindings. A function using both declaration kinds triggers a second parse with an exact log of up to 512 live names. On block exit the parser checks that block’s lexical names against its own and descendant `var` declarations. It passes hoisted names to the enclosing block and reclaims the closed lexical names. Nested functions own independent suffixes. Adjacent local overload signatures share the value binding of a matching implementation. A type-only module namespace can merge with an interface of the same name, and a function block can declare a local interface. A type-only namespace can contain up to eight levels of exported type-only namespaces. Each level sees a separate binding range and releases its member names after its closing brace. A global augmentation can declare a typed `var` without an initializer or an ambient function with at most one typed parameter and a return annotation. Modules mixing those two ambient member families use compatibility so their names can be checked together. A duplicate or incomplete scope delegates before it can publish comparison candidates.

The fast path accepts at most 1,048,576 source bytes, bounds expression and control recursion, and publishes up to 4,096 candidates. The addon starts with room for 64 candidates below 16 KiB and 128 candidates at larger input sizes before using its existing heap retry. Near the recursive stack limit, an uninterrupted run of singleton array wrappers can be read in flat passes. The reported depth still includes those wrappers and structures within the innermost array. Byte spans are half-open and relative to the original file. A comparison candidate contains the rule version, original operator, replacement operator, operator span, and both operand spans including syntactic parentheses. Candidates appear in source order of operator start, including nested comparisons. EOF must be reached before publishing the candidate buffer.

The versioned boundary rule is `comparison-boundary/v1`. Each of the four operators maps to the same strictness family with the equality bit toggled. Scope restrictions and UTF-8 validation precede the recognizer. The AST-free result is reported as `path: "fast"`.

After finding a module value-name collision, the native parser checks whether the full source is a sequence of simple `const` and `let` declarations with exactly one duplicate. The classifier supplies the first and repeated name spans in UTF-8 bytes once it reaches the end of the file. The compatibility parser handles other collisions, declarations and initializers. A native duplicate reports `path: "diagnostic"` and `reason: "duplicate-lexical"`.

When the Pulse parser declines a file, the normal build uses TypeScript's source parser and checks early syntax errors such as invalid assignment targets and duplicate bindings. It converts UTF-16 AST spans to UTF-8 bytes and reports a successful compatibility parse as `path: "fallback"` with `fallback: "typescript"`. A source error discards all candidates for that file. The compatibility diagnostics use their own wording and parser recovery.

The `--low-only` build compiles only the checked-in KaRaMeL C sources and the Node-API adapter. It can run `extract` in a checkout without npm dependencies. It reports a refusal for syntax outside the native grammar or over a resource limit.

Packaged installs use a generated syntax-only build of the pinned TypeScript compiler for compatibility parsing, threshold syntax and probe module classification. `npm run build:typescript-syntax` prepares it in a source checkout. The generator checks the upstream compiler digest, retains the declarations reachable from the extraction API and the required initializers, and copies the upstream license and notices. The package also installs the full compiler for witness and analysis APIs. A missing, incompatible or failing syntax build uses the full compiler. Once loaded, the full compiler serves these syntax consumers as well. Worker requests run in an isolated child process with a 16 MiB parser stack and use a dedicated pipe for the completed result. An ordinary caller retries through the same process if the parser exhausts its call stack. Exhausting the isolated resources raises a parser execution error.

Analysis maps ordered candidate byte offsets to UTF-16 line and column positions in one pass. The native scan uses 16-byte NEON or SSE2 blocks for ASCII without line endings. The scalar path handles other bytes and platforms. A verified Pulse byte reader recognizes U+2028 and U+2029 for both the grammar and the position scan.

## Verification and measurements

`TmtReference.fst` parses lexer outputs into a complete AST for the declaration grammar with simple operands. Its compact interpretation computes operand spans and ordered candidates without expression trees. F★ checks equality of the two interpretations for every token sequence in that model, including failure, and checks acceptance for all ASTs admitted by the independently written bounded grammar predicate and printer. The verified Pulse routines used by the native parser implement bounds-checked reads, maximal character-class scans, operator recognition, and indexed candidate writes. These contracts start with a live input buffer of the supplied length and an allocated output buffer of the supplied capacity. The control and member syntax participates in the native safety contract. Its candidate equivalence is checked against Yuku by the extraction audit.

`TmtPulseParser.fst` implements the actual AST-free native grammar, recursive descent, lexical modes and EOF handling. Its extracted C runs in the ordinary Node-API entry point. F★ and Pulse check termination, buffer ownership, bounded accesses, the candidate count on success, complete initialization of the published prefix, consumption of the entire input buffer on success, and zero published candidates on failure. The lexical duplicate classifier also verifies complete input consumption and ordered, nonempty spans within the source. The C adapter supplies distinct buffers and their real lengths. A typechecked example evaluates the reference on the exact TSX token sequence and checks the candidate span and rejection of a malformed suffix.

`native_operator_backpatch` connects the byte-level operator scanner and the production comparison emitter to the reference interpretation of a comparison. Given correct child candidates, operand spans and a reserved slot, it proves the output slice equals the reference candidate list including byte spans and order. The correspondence between the full byte-level parser and the F★ reference token model still requires proof of these premises throughout parsing and tokenization. Buffer allocation, UTF-8 validation, C compilation, and Node-API marshalling remain in the trusted execution boundary. `candidateBytes` measures candidate heap allocations in the native adapter. The fixed stack allocation and JavaScript output objects have separate storage. The AST counter is zero by construction for this native parser.

The [corpus audits](performance.md) use full TypeScript and Yuku as development references for ordered candidate fields and source acceptance with the comparison and JSX logical rules. They compare the full diagnostic record for native duplicate declarations and invalid encoding.

## Pulse native parser

`TmtPulseMemory.fst` separates the read-only fractional borrow of source bytes, the initialized binding table and candidate storage. Read-only grammar functions require only the source borrow and preserve the caller’s separate workspace through a polymorphic frame. The candidate writer owns slots through a Pulse mask and can write into uninitialized storage. It marks each slot after storing a candidate. The workspace invariant links every mark to an initialized slot. The parser clears the marks before its expanded retry and checks every slot below the final count. The exported parser ensures the prefix is initialized before the C adapter copies it. `TmtPulseScan.fst` proves the endpoint of the maximal byte-class scan and preserves the source. The other primitives prove exact byte, line-separator, comparison-token and candidate-slot behavior. The C adapter supplies a fresh initialized binding table and the real source and output lengths for each call.

F★ checks the grammar's existing mutually recursive termination measures. Grammar functions return Pulse `stt` computations. The sequencing helpers preserve each call in the extracted program, including writes whose result is discarded. F★ 2026.11.15 extracts the verified program through Custard `KrmlC` and KaRaMeL. KaRaMeL lowers source-length tail recursion to C loops. The native regression matrix checks in-limit and over-limit files in fresh processes.

On AArch64, the build can specialize the bounded comment and string scans with NEON. The build checks the fingerprints of all three complete scalar functions before lowering. The accelerated loop reads 16 bytes only when both the input and its fuel permit it, then resumes scalar processing at the first possible sentinel or at the end of the block. The checked-in generated C is the scalar reference for proof regeneration. Tests compare the compiled NEON and scalar results at every byte value and lane and at source boundaries. The NEON primitive is part of the trusted native build boundary.
