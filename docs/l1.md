# L1 grammar and candidate contract

The native grammar recognizes a bounded subset of TypeScript modules, a restricted control program, and a limited set of TSX initializers. Lexical rules operate on UTF-8 with ASCII identifiers and punctuation. The grammar below illustrates the control and JSX subset used by the reference model and initial native entry points. The module and expression extensions are described below it.

```text
file        ::= trivia (declaration ";"? | control statement* | var-init ";" statement*)? trivia EOF
declaration ::= "export"? "const" identifier "=" (parameter "=>" result | result)
parameter   ::= "(" identifier ":" "number" ")"
result      ::= comparison | element
comparison  ::= atom (operator atom)?
atom        ::= (identifier | "this") ("." property)* | decimal | "(" comparison ")"
operator    ::= "<" | "<=" | ">" | ">="
element     ::= "<" jsx-name attribute* "/" ">"
attribute   ::= jsx-name "=" (jsx-string | "{" comparison "}")
control     ::= "if" "(" comparison ")" block ("else" block)?
              | "while" "(" comparison ")" block
              | "do" block "while" "(" comparison ")" ";"?
              | "for" "(" (("let" | "var") identifier "=" comparison)? ";" comparison? ";" update? ")" block
block       ::= "{" statement* "}"
statement   ::= control | update ";" | ";"
var-init    ::= "var" identifier "=" comparison
update      ::= identifier ("++" | "--")
```

The ordinary lexical mode skips spaces, tabs, LF, CR, CRLF, U+2028, U+2029, and UTF-8 line and block comments. A hashbang at byte zero uses the same line terminators and preserves original byte positions. A line break, including one in a block comment, is forbidden between the parameter's closing parenthesis and the arrow. Identifiers have the ASCII structure of JavaScript identifiers without escapes and exclude reserved words. Declaration and parameter names also exclude `eval` and `arguments`. JSX names allow hyphens after the first character and have no reserved-word restriction. An unsigned decimal is an ASCII digit sequence with no leading zero except the literal zero. JSX attribute strings have matching single or double quotes and may contain UTF-8, including comparison punctuation. In JSX tag mode only spaces, tabs, and line endings separate tokens. In an attribute expression the ordinary lexical mode resumes.

Property names after a dot use ASCII identifier characters and may be reserved words. Prefix and postfix update expressions use the simple assignment-target rules. A postfix update permits no line break before the operator. A `var` loop initializer is allowed in a standalone file-scope control program. Classic loop heads admit bounded expression lists and typed `let` or `const` binding lists, including nested patterns. A simple `var` initializer is supported in a function. Loop bindings use a nested scope and are restored when the loop ends. The `var` reader accepts simple typed or initialized bindings. The bounded native route delegates a function that mixes `var` with potentially conflicting lexical declarations. Collection loops use `let` or `const` with an identifier or a bounded nested binding pattern. A switch can contain case tests, a single optional default clause, and a shared lexical scope. Unlabelled `break` requires an enclosing loop or switch. Unlabelled `continue` requires an enclosing loop. Both permissions reset at a function boundary. Try, catch, and finally bodies are explicit blocks. A catch can have no binding, a named binding, or a bounded nested binding pattern.

The module grammar accepts side-effect, named, default, and namespace imports and type-only default and named imports. Dynamic `import()` accepts a specifier and optional options expression. The `import.meta` expression is available throughout a module. Variables can bind simple names or nested object and array patterns, with array elisions, simple defaults and a final named rest binding. Simple mutable declarations can use a definite assignment marker with a type annotation. Default exports support assignment expressions and named or anonymous function and class declarations. A default export can appear once per module. Name tables distinguish module types from values and reserve both namespaces for imports and classes. Plain and type-only star and named re-exports accept a quoted source. Named re-exports support ASCII aliases, including `default`. Empty export lists are supported. Nonempty local export lists delegate for forward resolution. Simple `declare const`, `declare let` and `declare var` bindings require annotations. Nested function declarations, named and anonymous function expressions, and ordinary and async object methods share the bounded function-body parser. Named functions support optional typed parameters and default expressions. Functions can contain local type aliases, including the single statement of a control body. Function and arrow parameter lists admit a simple rest binding in the final slot. Await expressions and `for await…of` are available in modules and async bodies, with a fresh permission at every function boundary.

Class declarations can use bounded type parameters, a simple qualified base, and an implements list. The fast path reads uninitialized fields and ordinary, static, async and constructor methods. Methods can access `super` properties and derived constructors can call `super`. Arrows inherit these permissions. Ordinary functions reset them. Private and computed members, accessors, and field initializers delegate.

The type grammar accepts named and qualified references, nested type arguments, numeric, string and template literal types, bounded conditional types with inferred names, arrays, labeled and rest tuples, indexed access, grouped and function types, and object types with computed and ordinary properties, typed indexes, call signatures, constructor signatures and generic methods. Type aliases, interfaces, and named functions can use bounded type parameter lists with constraints and defaults. Interfaces accept bounded lists of qualified base references. Quoted ambient modules accept bodies containing plain or exported interfaces, which may merge. Function-like result positions admit type predicates and assertion signatures. A typed leading `this` parameter has no runtime binding. Type operators include `keyof` and qualified `typeof` queries. A quoted module specifier is supported in import types.

The expression parser uses precedence for comparisons, relational `in` and `instanceof`, arithmetic, equality, bitwise and logical operators, shifts, conditionals, and assignments. Assignments associate to the right and require a simple name, member, or computed target. Other supported forms include selected unary operators, `delete` on member and optional-chain expressions, strings, bounded numeric literals, template substitutions, calls, qualified constructors, sparse arrays, spreads, and computed names for object properties and methods. String values and template segments support fixed-width hexadecimal and Unicode escapes, bounded Unicode code points, and escaped line endings. Tagged templates retain the full tag and template span, including tags followed by a line break. The reader preserves raw escape spellings and parses substitutions. Calls with attached type arguments use read-only lookahead before the call parser consumes arguments. Member, index and call chains can use optional access. Nullish coalescing requires parentheses when mixed with `&&` or `||`. Arrow functions support type parameters, typed parameters with simple defaults, bounded nested binding patterns, return annotations, and expression or block bodies. In TSX the generic head must have a comma, constraint or default to distinguish it from an opening tag. TypeScript `as` and `satisfies` operators and postfix non-null assertions require no preceding line break. Unsupported angle bracket forms, including generic tags, and unsupported operators decline the entire file.

The regex literal reader supports ASCII classes and ranges, basic escapes including `\0` without a following decimal digit, numeric references to captures already opened, balanced capturing and noncapturing groups, ASCII named captures, lookarounds, alternation, quantifiers, and distinct `d`, `g`, `i`, `m`, `s`, `u`, and `y` flags. The flat scanner uses a loop in generated C. Group nesting is bounded at 32 and counted quantifiers use at most six decimal digits. Unrecognized regex forms delegate with the rest of the source.

TSX uses the expression parser for self-closing and paired elements, fragments, and nested JSX. Attribute values can be quoted, braced or nested JSX, and openings can use boolean and spread attributes. Inside children, raw text uses JSX lexical rules and braces return to ordinary expression parsing. Tag closures must match the opening name. A direct disjunction in a `disabled` attribute delegates to preserve the focused logical rewrite.

The module grammar records up to 512 top-level bindings and up to 512 bindings across the currently open function and block scopes, including parameters. A third region tracks up to 512 export names separately. Individual lists retain their own bounds. Speculative parameter and collection heads use scratch entries above the active scope. Arrow blocks share the statement parser's recursion budget, and closing a block restores the caller's active names. Duplicate or oversized bindings decline the entire module. If both recognizers decline an input, no partial candidates are published.

The fast path accepts at most 1,048,576 source bytes, bounds expression and control recursion, and publishes up to 4,096 candidates. Near the recursive stack limit, an uninterrupted run of singleton array wrappers can be read in flat passes. The reported depth still includes those wrappers and structures within the innermost array. Byte spans are half-open and relative to the original file. A comparison candidate contains the rule version, original operator, replacement operator, operator span, and both operand spans including syntactic parentheses. Candidates appear in source order of operator start, including nested comparisons. EOF must be reached before publishing the candidate buffer.

The versioned boundary rule is `comparison-boundary/v1`. Each of the four operators maps to the same strictness family with the equality bit toggled. Scope restrictions and UTF-8 validation precede the recognizer. The AST-free result is reported as `path: "fast"`.

After finding a module value-name collision, Low★ checks whether the full source is a sequence of simple `const` and `let` declarations with exactly one duplicate. The classifier supplies the first and repeated name spans in UTF-8 bytes once it reaches the end of the file. The compatibility parser handles other collisions, declarations and initializers. A native duplicate reports `path: "diagnostic"` and `reason: "duplicate-lexical"`.

When the Low★ parser declines a file, the normal build uses TypeScript's source parser and checks early syntax errors such as invalid assignment targets and duplicate bindings. It converts UTF-16 AST spans to UTF-8 bytes and reports a successful compatibility parse as `path: "fallback"` with `fallback: "typescript"`. A source error discards all candidates for that file. The compatibility diagnostics use their own wording and parser recovery.

The `--low-only` build compiles only the checked-in KaRaMeL C sources and the Node-API adapter. It can run `extract` in a checkout without npm dependencies. It reports a refusal for syntax outside Low★ or over a resource limit.

Packaged installs use a generated syntax-only build of the pinned TypeScript compiler on the first compatibility parse. `npm run build:typescript-syntax` prepares it in a source checkout. The generator checks the upstream compiler digest, retains the declarations reachable from the extraction API and the required initializers, and copies the upstream license and notices. The package also installs the full compiler for witness and analysis APIs. A missing, incompatible or failing syntax build uses the full compiler. If the full compiler is already loaded, compatibility parsing reuses it. Worker requests run in an isolated child process with a 16 MiB parser stack and use a dedicated pipe for the completed result. An ordinary caller retries through the same process if the parser exhausts its call stack. Exhausting the isolated resources raises a parser execution error.

Analysis maps ordered candidate byte offsets to UTF-16 line and column positions in one pass. The native scan uses 16-byte NEON or SSE2 blocks for ASCII without line endings. The scalar path handles other bytes and platforms. A checked Low★ byte reader recognizes U+2028 and U+2029 for both the grammar and the position scan.

## Verification and measurements

`TmtReference.fst` parses lexer outputs into a complete AST for the declaration grammar with simple operands. Its compact interpretation computes operand spans and ordered candidates without expression trees. F★ checks equality of the two interpretations for every token sequence in that model, including failure, and checks acceptance for all ASTs admitted by the independently written bounded grammar predicate and printer. The verified Low★ routines used by the native parser implement bounds-checked reads, maximal character-class scans, operator recognition, and indexed candidate writes. These contracts start with a live input buffer of the supplied length and an allocated output buffer of the supplied capacity. The control and member syntax participates in the native safety contract. Its candidate equivalence is checked against Yuku by the extraction audit.

`TmtParser.fst` implements the actual AST-free native grammar, recursive descent, lexical modes and EOF handling. Its extracted C runs in the ordinary Node-API entry point. Low★ checks termination, live-memory preconditions, bounded buffer accesses, the candidate count on success, consumption of the entire input buffer on success, and zero published candidates on failure. The lexical duplicate classifier also verifies complete input consumption and ordered, nonempty spans within the source. The C adapter supplies distinct buffers and their real lengths. A typechecked example evaluates the reference on the exact TSX token sequence and checks the candidate span and rejection of a malformed suffix.

`native_operator_backpatch` connects the byte-level operator scanner and native candidate write to the reference interpretation of a comparison. Given correct child candidates, operand spans and a reserved slot, it proves the output slice equals the reference candidate list including byte spans and order. The correspondence between the full byte-level parser and the F★ reference token model still requires proof of these premises throughout parsing and tokenization. Buffer allocation, UTF-8 validation, C compilation, and Node-API marshalling remain in the trusted execution boundary. `candidateBytes` measures candidate heap allocations in the native adapter. The fixed stack allocation and JavaScript output objects have separate storage. The AST counter is zero by construction for this native parser.

The [corpus audits](performance.md) use Yuku as a development reference for ordered candidate fields and source acceptance with the comparison and JSX logical rules. They compare the full diagnostic record for native duplicate declarations and invalid encoding.
