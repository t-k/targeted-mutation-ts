# L1 grammar and candidate contract

L1 version 1 uses a single declaration or an empty file. Its lexical rules are defined over UTF-8, with ASCII identifiers and punctuation. The module dialect permits the initial `export`. A JSX initializer is available only in TSX.

```text
file        ::= trivia (declaration ";"?)? trivia EOF
declaration ::= "export"? "const" identifier "=" (parameter "=>" result | result)
parameter   ::= "(" identifier ":" "number" ")"
result      ::= comparison | element
comparison  ::= atom (operator atom)?
atom        ::= identifier | decimal | "(" comparison ")"
operator    ::= "<" | "<=" | ">" | ">="
element     ::= "<" jsx-name attribute* "/" ">"
attribute   ::= jsx-name "=" (jsx-string | "{" comparison "}")
```

The ordinary lexical mode skips spaces, tabs, LF, CRLF, ASCII line comments, and block comments. A line break, including one in a block comment, is forbidden between the parameter's closing parenthesis and the arrow. Identifiers have the ASCII structure of JavaScript identifiers without escapes and exclude reserved words. Declaration and parameter names also exclude `eval` and `arguments`. JSX names use the same structure without the reserved-word restriction. An unsigned decimal is an ASCII digit sequence with no leading zero except the literal zero. JSX attribute strings have matching single or double quotes and may contain UTF-8, including comparison punctuation. In JSX tag mode only spaces, tabs, and line endings separate tokens. In an attribute expression the ordinary lexical mode resumes.

The fast path accepts at most 1,048,576 source bytes, a depth of 64 parenthesized expressions, and 4,096 candidates. Byte spans are half-open and relative to the original file. A comparison candidate contains the rule version, original operator, replacement operator, operator span, and both operand spans including syntactic parentheses. Candidates appear in source order of operator start, including nested comparisons. EOF must be reached before publishing the candidate buffer.

The versioned boundary rule is `comparison-boundary/v1`. Each of the four operators maps to the same strictness family with the equality bit toggled. Scope restrictions and UTF-8 decoding precede the recognizer. A fast-path miss hands the entire file and dialect to Yuku. A Yuku diagnostic makes the operation fail without publishing a candidate prefix.

## Verification and measurements

`TmtReference.fst` parses lexer outputs into a complete AST for L1. Its compact interpretation computes operand spans and ordered candidates without expression trees. F★ checks equality of the two interpretations for every token sequence, including failure, and checks acceptance for all ASTs admitted by the independently written bounded grammar predicate and printer. The verified Low★ routines used by the native parser implement bounds-checked reads, maximal character-class scans, operator recognition, and indexed candidate writes. These contracts start with a live input buffer of the supplied length and an allocated output buffer of the supplied capacity.

The native recursive grammar driver, lexer mode switching and token-to-source correspondence, buffer ownership across Node-API, and C compilation remain trusted. The checked F★ theorems presently cover the token model and checked buffer routines. Whole-file correspondence for the native driver is exercised by the ordinary CLI acceptance suite and the independent Yuku comparison.

The corpus report checks every returned candidate field and diagnostic status. The TypeScript corpus is the sparse checkout of `tests/cases/compiler` at the reported revision, including intentional parse failures and raw encoding fixtures. For a fallback file the product currently invokes the reference parser itself, so independent parser agreement is measured on fast files. None of the Vite and Preact files used the fast grammar. Twenty compiler fixtures used it and produced no comparison candidates. The controlled TS/TSX fixtures exercise the nonempty native output. A performance claim needs a broader grammar and a native-to-native benchmark under comparable conditions.
