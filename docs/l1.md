# L1 grammar and candidate contract

The native grammar recognizes an empty file, a single constant declaration, or a restricted control program. Lexical rules operate on UTF-8 with ASCII identifiers and punctuation. The module dialect permits the `export` prefix in a constant declaration. A JSX initializer is available in TSX.

```text
file        ::= trivia (declaration ";"? | control statement* | var-init ";" statement*)? trivia EOF
declaration ::= "export"? "const" identifier "=" (parameter "=>" result | result)
parameter   ::= "(" identifier ":" "number" ")"
result      ::= comparison | element
comparison  ::= atom (operator atom)?
atom        ::= (identifier | "this") ("." property)* | decimal | "(" comparison ")"
operator    ::= "<" | "<=" | ">" | ">="
element     ::= "<" jsx-name attribute* "/" ">"
attribute   ::= jsx-name "=" (jsx-string | "{" comparison "}")
control     ::= "if" "(" comparison ")" block ("else" block)?
              | "while" "(" comparison ")" block
              | "do" block "while" "(" comparison ")" ";"?
              | "for" "(" (("let" | "var") identifier "=" comparison)? ";" comparison? ";" update? ")" block
block       ::= "{" statement* "}"
statement   ::= control | update ";" | ";"
var-init    ::= "var" identifier "=" comparison
update      ::= identifier ("++" | "--")
```

The ordinary lexical mode skips spaces, tabs, LF, CRLF, ASCII line comments, and block comments. A line break, including one in a block comment, is forbidden between the parameter's closing parenthesis and the arrow. Identifiers have the ASCII structure of JavaScript identifiers without escapes and exclude reserved words. Declaration and parameter names also exclude `eval` and `arguments`. JSX names allow hyphens after the first character and have no reserved-word restriction. An unsigned decimal is an ASCII digit sequence with no leading zero except the literal zero. JSX attribute strings have matching single or double quotes and may contain UTF-8, including comparison punctuation. In JSX tag mode only spaces, tabs, and line endings separate tokens. In an attribute expression the ordinary lexical mode resumes.

Property names after a dot use ASCII identifier characters and may be reserved words. A postfix update permits no line break before the operator. A `var` loop initializer is allowed in a standalone file-scope control program. Nested loop declarations use `let`. An unbraced control body can contain a simple statement. Nested control statements require braces.

The module grammar accepts side-effect, named, default, and namespace imports and simple named type import modifiers. It supports initialized `const` and `let` declarations, plain named functions, and async declarations whose bodies fit the supported grammar. Functions can use a single unconstrained type parameter, nested generic type references, and array and union annotations. Function bodies admit scoped declarations, control blocks, ordinary expression statements, returns, and throws.

The expression parser uses operator precedence for comparisons, arithmetic, equality, bitwise and logical operators. It supports conditional expressions, selected unary operators, strings, a restricted regular expression syntax, template substitutions, ordinary calls, indexed access, simple constructor calls, compound values, and short expression-bodied arrows. A TypeScript non-null assertion requires no preceding line break. Ambiguous angle brackets, tagged templates, and unsupported operators decline the entire file. JSX `disabled` attributes containing a direct disjunction are delegated to preserve the existing logical rewrite.

The module grammar records up to 64 top-level bindings and up to 64 bindings across the currently open scopes of a function, including its parameters. Bound names are stored as byte spans in a fixed scratch buffer. Duplicate or oversized bindings decline the entire module. If both recognizers decline an input, no partial candidates are published.

The fast path accepts at most 1,048,576 source bytes, bounds expression and control recursion, and publishes up to 4,096 candidates. In the normal build, an expression-depth refusal in module mode reaches the broad native parser before the Yuku fallback. Byte spans are half-open and relative to the original file. A comparison candidate contains the rule version, original operator, replacement operator, operator span, and both operand spans including syntactic parentheses. Candidates appear in source order of operator start, including nested comparisons. EOF must be reached before publishing the candidate buffer.

The versioned boundary rule is `comparison-boundary/v1`. Each of the four operators maps to the same strictness family with the equality bit toggled. Scope restrictions and UTF-8 validation precede the recognizer. The AST-free result is reported as `path: "fast"`.

When a module falls outside the Low★ grammar, the addon can parse it with a statically linked Oxc 0.159.0. Oxc builds a native AST and checks syntax and module semantics. TMT checks known differences with Yuku, locates operator tokens at the AST operand boundaries, and validates each relational edit with the Low★ byte classifier. The addon passes only ordered candidate rows and metrics to JavaScript, reported as `path: "native"`. The broad parser has byte and recursion budgets and runs its AST passes on a separate stack on the calling thread.

Files declined by the addon and scripts outside L1 are parsed by Yuku, whose AST and token offsets are converted back to byte offsets. Yuku supplies the diagnostic text for declined files. A diagnostic discards all candidates for that file.

The `--low-only` build compiles only the checked-in KaRaMeL C sources and the Node-API adapter. It can run `extract` in a checkout without npm dependencies. It reports a refusal for syntax outside Low★ or over a resource limit, so the supported grammar can be measured independently of either fallback.

After checking the fallback diagnostics, TMT inspects the token kinds before reading Yuku's lazily decoded AST. Files without a relevant comparison or JSX logical token need no AST for mutation extraction. Analysis maps ordered candidate byte offsets to UTF-16 line and column positions in one pass. The native scan uses 16-byte NEON or SSE2 blocks for ASCII without line endings. The scalar path handles other bytes and platforms. A checked Low★ byte reader recognizes U+2028 and U+2029 for both the grammar and the position scan.

For TypeScript, the token check can extract a complete file's candidates when each comparison is a direct `if`, `while`, or classic `for` condition with simple name, number, or property operands. A simple generic annotation on a leading ambient `const` can account for a pair of type angle tokens. When any relational token falls outside these shapes, the AST supplies the complete result. A token-assisted result reports `path: "fallback"` with `fallback: "tokens"`. Yuku's full-file syntax and semantic diagnostics run in both fallback paths.

## Verification and measurements

`TmtReference.fst` parses lexer outputs into a complete AST for the declaration grammar with simple operands. Its compact interpretation computes operand spans and ordered candidates without expression trees. F★ checks equality of the two interpretations for every token sequence in that model, including failure, and checks acceptance for all ASTs admitted by the independently written bounded grammar predicate and printer. The verified Low★ routines used by the native parser implement bounds-checked reads, maximal character-class scans, operator recognition, and indexed candidate writes. These contracts start with a live input buffer of the supplied length and an allocated output buffer of the supplied capacity. The control and member syntax participates in the native safety contract. Its candidate equivalence is checked against Yuku by the extraction audit.

`TmtParser.fst` implements the actual AST-free native grammar, recursive descent, lexical modes and EOF handling. Its extracted C runs in the ordinary Node-API entry point. Low★ checks termination, live-memory preconditions, bounded buffer accesses, the candidate count on success, consumption of the entire input buffer on success, and zero published candidates on failure. The C adapter supplies distinct buffers and their real lengths. A typechecked example evaluates the reference on the exact TSX token sequence and checks the candidate span and rejection of a malformed suffix.

`native_operator_backpatch` connects the byte-level operator scanner and native candidate write to the reference interpretation of a comparison. Given correct child candidates, operand spans and a reserved slot, it proves the output slice equals the reference candidate list including byte spans and order. The correspondence between the full byte-level parser and the F★ reference token model still requires proof of these premises throughout parsing and tokenization. Buffer allocation, UTF-8 validation, C compilation, and Node-API marshalling remain in the trusted execution boundary. `candidateBytes` measures candidate heap allocations in the native adapter. The fixed stack allocation and JavaScript output objects have separate storage. The AST counter is zero by construction for this native parser.

The [broad extraction report](../evidence/m1/broad-native-extraction.json) compares all ordered candidate fields and diagnostics with Yuku, including a separate Vite production-source run that extracted 160 candidates from 118 files without loading Yuku. The F★ theorems cover the reference model and the Low★ routines. Compatibility between the broad parser and Yuku is checked by regression tests and differential runs.
